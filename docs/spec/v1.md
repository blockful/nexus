## 2. Architecture (frozen)

Modular router, **no proxy, no admin key**:

- **Core** (`GovernorNexus`): unmodified OZ Governor v5.6.1 by inheritance
  (`Governor` + `GovernorSettings` + `GovernorVotes` + `GovernorTimelockControl`).
  Owns proposal lifecycle, vote casting, and the timelock relationship. Dispatches
  vote *counting*, quorum, success criteria, voting period, and proposer eligibility
  to the ruleset bound to each proposal.
- **Rulesets** (`IRuleset`): one per proposal type (Standard / Optimistic / Bond at
  launch). State-changing hooks callable only by the governor. Parameters owned by
  the timelock. Registered/replaced only via `setRuleset` (`onlyGovernance` — full
  DAO vote through the timelock). One-shot deployer bootstrap (`initializeRulesets`).
- **Ruleset address pinned per proposal at creation** — replacing a type's ruleset
  never affects live proposals.
- Proposal type declared at creation (`proposeWithType`), immutable. Plain
  `propose()` routes to Standard, preserving the stock `IGovernor` interface.
- **Untouched:** ENS token `0xC183…9D72` and Timelock `0xFe89…44b7`. Migration is a
  role grant to the new governor + revoke of the old one; the treasury never moves.

### Proposal types at launch

| Type | Success rule | Quorum | Period | Proposer eligibility |
|---|---|---|---|---|
| Standard (0) | For > Against | 1M ENS (For+Abstain) | default | ≥ 100k ENS threshold, enforced continuously |
| Optimistic (1) | passes unless Against ≥ 500k ENS | none | 15 days | proposer allowlist AND (target, selector) action allowlist, value = 0 |
| Bond (2) | For > No + No+Slash | 1M ENS | default | bond stake, no threshold |

## 4. Method (frozen — agreed 2026-07-06)

Risk-calibrated hybrid:

- **Clean-room** (production-precedent study → mini-spec → TDD → differential run vs
  the draft → written verdict) for the architecture and the novel mechanisms
  (ruleset dispatch, mutable votes, anti-snipe, optimistic, bond).
- **Direct review of the draft** for trivial features (batch voting, self-cancel,
  active limit).
- **The comparison instrument is the differential harness in this repo**
  (`test/differential/`): the draft's 46 tests as shared vectors, one binding per
  implementation. "Matches the draft" is a test run, not an opinion.
- Starting point is this repo's stock OZ v5.6.1 scaffold with fork-proven parity
  against the live governor — NOT a fork of the current governor, and NOT the draft
  codebase (draft stays a pinned, vendored reference at `lib/governor-nexus-draft`,
  commit `87d659b` — provenance recorded there).

### Vector surface (frozen)

`test/differential/ISystemUnderTest.sol` freezes the ABI surface the vectors exercise
(function selectors and error signatures mirroring the draft v0.1 public API). The
production implementation must satisfy it as written; loosening any part of it —
renaming an error, changing a signature — is an amendment to this spec, with the
reasoning recorded here.

## 5. Baseline parity (established, milestone 0)

The fork suite (`test/fork/`, mainnet fork at block 25,445,220, real token + timelock,
nick.eth as the common delegate) proves the scaffold is behaviorally equivalent to the
live governor: configuration getters, quorum output, voting-power reads, proposal id
hashing, and the full propose → vote → queue → execute lifecycle including timelock eta
and execution effects.

**Pinned v4→v5 divergences** (asserted in `ForkParityDivergencesTest`, all
inconsequential post-migration):
1. Quorum fraction encoding: 100/10000 live vs 1/100 scaffold — identical quorum output.
2. v5 checkpoints the quorum numerator from deployment; `quorum()` for pre-deployment
   timepoints returns 0 (live v4 answers any past timepoint).
3. Revote rejection: v4 require-string vs v5 typed error — same behavior.

A/B gas on the same fork (live governor vs stock v5 scaffold): propose 115k → 93k ·
castVote 107k → 102k · queue 102k → 120k · execute 79k → 57k. The draft's own numbers
(vs Nexus draft) live in the draft repo's benchmark; the three-way comparison
(live / stock v5 / Nexus) is the milestone-9 report input.

## 7. Migration (frozen, with one correction)

Per the RFC: deploy → audit → DAO proposal granting the new governor timelock roles →
route new proposals through it → revoke the old governor.

**Correction carried from the 2026-07-02 notes:** the live ENS timelock is OZ v4.3 —
`CANCELLER_ROLE` does not exist there (introduced in v4.8; cancellation authority is
`PROPOSER_ROLE`). Migration docs and deploy scripts must grant **PROPOSER + EXECUTOR
only**. The draft's README/Deploy.s.sol still mention CANCELLER_ROLE; this repo's fork
fixture already does it correctly.
